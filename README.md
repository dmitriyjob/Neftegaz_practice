# Кластеризация нефтедобывающих скважин

Учебный проект по предмету **«Анализ данных в нефтегазе 26/27»**, тема 9.
Задача: объяснить основные методы кластеризации, сгруппировать скважины по
характеристикам и интерпретировать результат на открытых отраслевых данных.

Основной кейс использует **реальную месячную отчётность BOEM OGOR-A за 2023 год**.
Из 74 986 исходных записей по 5 992 API отобраны 1 387 нефтяных стволов.
Одна строка модели соответствует одному 12-значному API, включая боковой ствол.
Исходный ZIP сохранён в проекте и проверяется по SHA256, поэтому для повторения
расчёта интернет не нужен.

K-means выделил две группы: **846 и 541 ствол**, средний силуэт **0,412**.
Медианный дебит составляет 51,9 и 1 592,1 барр./сут работы, обводнённость 85,0% и 12,6%.
При замене StandardScaler на RobustScaler ARI снижается до 0,211: состав групп
существенно зависит от способа масштабирования. Это ограничение явно разобрано в работе.

## Воспроизведение

Используйте Python 3.12. Эта версия проверена для расчёта и тестов проекта.

```bash
git clone https://github.com/dmitriyjob/Neftegaz_practice.git
cd Neftegaz_practice
python -m venv .venv
```

Активируйте окружение:

```bash
# Linux / macOS
source .venv/bin/activate
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Затем установите зависимости и выполните полный расчёт:

```bash
python -m pip install -r requirements.txt
python run_analysis.py
python -m unittest discover -s tests -v
```

`run_analysis.py` проверяет исходный снимок, заново готовит выборку, обучает модель,
считает диагностику и сохраняет все результаты в `results/boem_2023/`.
Для проверки в отдельном каталоге: `python run_analysis.py --output results/check`.
Команда в отчёте и `run_manifest.json` сохраняет выбранный каталог. Поле `argv`
содержит аргументы отдельно; строка `command` использует POSIX-кавычки для путей
с пробелами и другими специальными символами.
Если относительный путь невозможен, например между разными дисками Windows,
сохраняется абсолютный аргумент, а ссылки отчёта используют файловые URI.
Презентация и реферат строятся отдельно из `summary.json`; инструкции ниже.

## Что и зачем сравнивается

Скважины группируются по трём годовым характеристикам:

| Признак | Формула | Единицы |
| --- | --- | --- |
| Дебит нефти на день работы | сумма нефти / сумма дней добычи | барр./сут работы |
| Обводнённость | 100 × сумма воды / (сумма нефти + сумма воды) | % |
| Газовый фактор | 1000 × сумма газа в Mcf / сумма нефти | станд. куб. фут/барр. |

Отношения считаются по суммам объёмов за год. Это отличается от среднего
месячных отношений. Дебит на день работы отличается от календарного дебита.

В исходной отчётности одна строка относится к **completion за месяц**.
У одного API могут быть несколько эксплуатационных объектов. Для однозначного
подсчёта дней оставлены стволы с одним активным completion за год, без закачки, с нефтяным кодом,
корректным статусом, отчётностью за 12 месяцев и добычей нефти минимум в 9 месяцах.
[Таблица отбора](data/boem/attrition.csv) показывает потери на каждом шаге.

Перед K-means для дебита и газового фактора применяется `log1p`, затем все три
признака приводятся к сопоставимому масштабу через `StandardScaler`.
В расчёт расстояний не включены идентификаторы, оператор, время и будущие показатели.
Рассматриваются k от 2 до 8, `n_init=20`, `random_state=42`; выбран максимум среднего
силуэта. PCA используется только для изображения результатов.

Проверки включают смену seed, десять подвыборок по 80% стволов, сравнение с Ward,
другим масштабированием, отказом от логарифмирования, исключением газового фактора
и отдельными моделями для двух полугодий. ARI сравнивает разбиения и не является
«точностью» без эталонной разметки. Все фактические значения доступны в отчёте.

Практическое применение: найти сопоставимые группы, выбрать конкретные скважины
для изучения обводнения, газового фактора и сохранения добычи. Само разбиение
не устанавливает причины различий и не обосновывает ремонт или закрытие скважин.

## Структура и результаты

| Файл | Назначение |
| --- | --- |
| `prepare_boem.py` | Проверка ZIP, схемы и качества, отбор API, расчёт признаков |
| `cluster_wells.py` | Общая реализация подготовки и K-means, также работает с другими CSV |
| `run_analysis.py` | Основной BOEM-кейс, диагностика, единый источник чисел для материалов |
| `data/boem/source_manifest.json` | Источник, словарь, условия использования, SHA256, единицы |
| `data/boem/well_features.csv` | Один годовой профиль на API с исходными годовыми суммами |
| `data/boem/monthly_selected.csv` | Исходные месячные записи выбранных API |
| `results/boem_2023/summary.json` | Числа для реферата и презентации |
| `results/boem_2023/well_clusters.csv` | Профиль, группа и индивидуальный силуэт каждого API |
| `results/boem_2023/cluster_medians.csv` | Медианы характеристик групп в физических единицах |
| `results/boem_2023/cluster_profiles.csv` | Средние характеристик групп в физических единицах |
| `results/boem_2023/representative_wells.csv` | Ближайший к центру модели пример из каждой группы |
| `results/boem_2023/run_manifest.json` | Параметры, версии пакетов и хеши исходников/данных |

Групповые медианы в реферате и презентации описывают типичные значения. Они
не равны центрам K-means, которые определены в преобразованном пространстве.
Номера групп условны и упорядочены по среднему дебиту.

## Сборка реферата и презентации

Готовые файлы включены в репозиторий, для просмотра ничего устанавливать не нужно.
После изменения расчёта сначала выполните `python run_analysis.py`.

Для Word нужен `python-docx==1.2.0`:

```bash
python -m pip install -r requirements-docs.txt
python scripts/build_report.py
```

Презентацию собирает `scripts/build_presentation.mjs` через `@oai/artifact-tool`
из среды Codex. Этот пакет не входит в открытые Python-зависимости проекта.
Для сборки нужны Node.js и три переменные окружения:

| Переменная | Путь в среде Codex |
| --- | --- |
| `RUNTIME_NODE_MODULES` | Каталог `node_modules` с пакетом `@oai/artifact-tool` |
| `PRESENTATION_SKILL_DIR` | Каталог навыка презентаций с `container_tools` |
| `RUNTIME_PYTHON` | Исполняемый файл Python из комплектного runtime |

После задания путей выполните:

```bash
node scripts/build_presentation.mjs --finalize --output .build/final/presentation-reviewed.pptx --render-dir .build/preview
```

Финализатор проверяет структуру PPTX и встроенные данные диаграмм. Он требует
нового пути `--output` и не перезаписывает существующий файл. Готовый PPTX сохраняется
в отдельном каталоге `.build/final`, служебные файлы проверки — в `.build/presentation`.
После сборки
осмотрите все PNG из каталога рендеров и сохраните проверенный PPTX как
`presentation.pptx`. Диаграммы и таблицы в нём редактируются. Для основного
расчёта и сборки Word среда Codex не требуется.

## Другие CSV и синтетическая проверка

Общий интерфейс сохранён:

```bash
python cluster_wells.py --demo --output results/demo
python cluster_wells.py --input data/boem/well_features.csv --features Oil_Rate_bpd Water_Cut_pct GOR_scf_bbl --log-features Oil_Rate_bpd GOR_scf_bbl --output results/custom
```

Входной CSV должен быть в UTF-8 (допускается BOM), без NUL-символов, с уникальными заголовками
и одинаковым числом полей во всех записях. Для пропуска оставьте пустое поле
между разделителями. `--sep` принимает один символ, например `;` или табуляцию;
`--decimal ,` задаёт десятичную запятую. Разделители и переводы строк внутри
кавычек поддерживаются. Неоднозначные заголовки и строки с лишними или
недостающими полями отклоняются до анализа.

`--demo` создаёт явно искусственные данные с заранее разделёнными группами.
Это тест алгоритма, а не практический результат исследования. Повторные измерения
произвольного CSV агрегируются медианой по `Well_ID`; конфликт `Field_ID` для одного
ID отклоняется. Для промысловых объёмов используйте специальную подготовку BOEM,
потому что отношения годовых сумм нельзя заменять медианами сырых строк.

Старые `data/Oil_Gas.csv` и `results/oil_gas/` сохранены как архив исходной версии.
Их происхождение **не подтверждено**. Даты доходят до 2028 года, смысл изменений
глубины и единицы газового фактора требуют объяснения. Эти файлы не используются
в новом реферате и презентации и не выдаются за реальные промысловые данные.
