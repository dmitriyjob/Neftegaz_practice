# Открытые данные BOEM за 2023 год

Практическая часть использует отчетную добычу нефтяных скважин на федеральном шельфе Мексиканского залива (в текущей навигации сайта BOEM регион обозначен GOAR). Источник: Bureau of Ocean Energy Management, U.S. Department of the Interior, Oil and Gas Operations Reports, Part A (OGOR-A).

- [Инструкция ONRR: статусы скважин, газлифт и учет дней при закачке, приложение H](https://onrr.gov/document/MPRH-Appendix-H.pdf).

Архив скачан непосредственно с сервера BOEM 16 ноября 2026 года. BOEM разрешает копирование и распространение публичной информации с указанием источника и рекомендует получать данные непосредственно с серверов ведомства. Данные не объявляются в этом проекте материалом под лицензией Creative Commons. BOEM предупреждает о возможных ошибках и последующих исправлениях отчетности.

Год в имени файла обозначает период добычи, а не версию выгрузки. В репозитории сохранен конкретный снимок, чтобы последующие изменения базы не изменили результаты незаметно:

## Что считается скважиной

Исходная строка относится к эксплуатационному объекту `completion` за месяц. Один ствол может иметь несколько таких объектов. Итоговая строка `well_features.csv` относится к уникальному 12-значному API. Этот идентификатор включает двухзначный код бокового ствола, поэтому точное обозначение единицы анализа: **скважина (ствол по API)**. Стволы одной физической скважины могут иметь разные API и не считаются независимыми геологическими экспериментами.

Чтобы не задвоить дни работы параллельных объектов, отбираются только API с одним активным `completion` за весь год. Его ключ: лицензия, название completion и код интервала. Активность означает положительное число дней работы или положительный объем нефти, газа либо воды. Нулевые неработающие объекты сохраняются в месячном файле для проверки полноты.

Положительной добычи нефти недостаточно для отнесения скважины к нефтяным: газовая скважина тоже может давать конденсат. Поэтому во всех исходных записях выбранного API требуется код продукта `O`, а активные записи должны иметь нефтедобывающий статус `08`, `09`, `10` или `19`. В выбранном снимке встречаются активные статусы 08, 09 и 10.

API с положительным `Injection_Volume` хотя бы в одной записи исключаются. Согласно инструкции ONRR, нефтедобывающий статус 08 допускает циклы добычи и закачки, а статус 10 допускает закачку нефти для искусственного подъема или обработки. Без раздельного учета дней нельзя однозначно вычислить дебит на день добычи. Этот фильтр исключил API `177104096103`, у которого в двух месяцах указана закачка 7 131 и 707 единиц исходного поля. Единицы закачки зависят от типа операции и не использовались в расчетах.

## Проверки качества и отбор

До отбора скрипт проверяет схему из 19 полей, 12 цифр в API, календарные месяцы 2023 года, отсутствие точных дубликатов и повторов ключа completion-month, целочисленные неотрицательные объемы и число дней не больше календарной продолжительности месяца. При нарушении проверок выполнение прекращается, автоматическая подстановка значений не применяется. Для сохраненного снимка все эти проверки проходят.

В этом расчете положительный объем при нуле дней также останавливает подготовку и требует отдельного разбора. Это ограничение подготовки выбранного снимка, а не универсальный признак ошибки OGOR-A: инструкция ONRR допускает такие записи для статуса [02 — Inactive Drilling, с тестовой добычей](https://onrr.gov/document/MPRH-Appendix-H.pdf#page=2) и [17 — Well Work in Progress](https://onrr.gov/document/MPRH-Appendix-H.pdf#page=8). В сохраненной выгрузке таких строк нет.

| Шаг | Осталось API | Исключено на шаге | Причина |
|---|---:|---:|---|
| Исходный набор | 5 992 | 0 | 74 986 записей completion-month |
| Есть добыча нефти | 2 208 | 3 784 | Положительный объем хотя бы в одном месяце |
| Только код продукта O | 1 797 | 411 | Исключены газовые, смешанные и неизвестные объекты |
| Нефтедобывающие активные статусы | 1 797 | 0 | Статусы 08, 09, 10, 19 |
| Отчетность за все 12 месяцев | 1 756 | 41 | Общий календарный период наблюдения |
| Один активный completion за год | 1 688 | 68 | Однозначное суммирование дней работы |
| Не более одной активной записи на API-month | 1 688 | 0 | Дополнительная защита от двойного счета |

| Нет сообщенной закачки | 1 387 | 1 | Исключены смешанные дни добычи и закачки |

Подробная машинная таблица потерь находится в `attrition.csv`. Порог девять месяцев является заранее выбранным правилом учебной выборки, а не универсальным отраслевым стандартом. Эти фильтры ограничивают выводы относительно регулярно работавшим нефтяным фондом. Новые, долго простаивавшие и неоднозначно агрегируемые скважины не представлены.

## Признаки модели

| Столбец | Расчет по всем месяцам 2023 года | Единицы |
|---|---|---|
| `Oil_Rate_bpd` | Сумма нефти / сумма дней работы единственного активного completion | bbl/day |
| `Water_Cut_pct` | 100 × сумма воды / (сумма нефти + сумма воды) | % |
| `GOR_scf_bbl` | 1000 × сумма газа в Mcf / сумма нефти | scf/bbl |

`Oil_Rate_bpd` означает добычу на отчетный день работы. Это не календарный дебит и не потенциальная производительность при стандартных условиях. Обводненность и газонефтяное отношение вычисляются как отношения годовых сумм, а не как невзвешенные средние месячных отношений. GOR характеризует отчетное соотношение газа и нефти и сам по себе не доказывает изменение пластовых условий. Согласно инструкции ONRR для статуса 09, газ в OGOR-A отражает пластовую добычу за вычетом купленного или закачанного газлифтного газа. Поэтому высокий GOR нельзя автоматически объяснять включением газлифтного газа в числитель.

Идентификаторы, год, число месяцев, дни работы, годовые объемы, код участка и месторождения служат для проверки и интерпретации. Они не входят в евклидовы расстояния модели. `First_Production_Date` из исходного файла не используется как возраст скважины: словарь BOEM описывает это поле через начало добычи lease.

## Файлы и повторный запуск

- `ogora2023delimit.zip`: неизмененный официальный исходник, нужен для автономного запуска.
- `source_manifest.json`: URL, дата получения, версия снимка, контрольные суммы, формулы и размеры выборки.
- `well_features.csv`: 1 387 строк, одна на API, три модельных признака и поясняющие поля.
- `monthly_selected.csv`: исходные строки выбранных API, включая неактивные completions, для проверки агрегации и сравнения полугодий. Точное число строк записано в `source_manifest.json`.
- `attrition.csv`: последовательность отбора с числом исключенных API и оставшихся исходных строк.

Из корня репозитория:

```bash
python prepare_boem.py
python -m unittest discover -s tests -p test_boem.py -v
```

Подготовка работает без интернета и воспроизводит CSV из включенного архива. Необязательный `python prepare_boem.py --download` заново получает источник, но принимает только снимок с ожидаемой SHA256. Если BOEM обновил архив, скрипт сообщает об изменении версии и не перезаписывает сохраненный файл. Для перехода на новую редакцию требуется отдельное осознанное обновление контрольной суммы и результатов.

API, номер лицензии и даты при чтении CSV нужно сохранять строками:

```python
monthly = pd.read_csv(
    "data/boem/monthly_selected.csv",
    dtype={"API_Well_Number": str, "Production_Date": str, "Lease_Number": str},
)
```

Для сравнения полугодий агрегируются те же API и те же формулы отдельно за `202301`…`202306` и `202307`…`202312`. В selected-выборке неактивные записи имеют нулевые дни и объемы. Суммировать дни в полном исходном наборе без отбора нельзя. Данные каждого полугодия следует преобразовывать масштабированием, обученным на годовой выборке, если сравниваются присвоения к одним годовым центрам.

## Пределы интерпретации

Результат описывает сочетания добычи, обводненности и газонефтяного отношения в 2023 году. Выборка охватывает разные месторождения, поэтому различия могут отражать и геологию, и режим эксплуатации. В данных нет достаточной информации о пластовом давлении, проницаемости, причинах остановок, себестоимости и ремонтах. Кластеры подходят для предварительного выделения групп, требующих дальнейшего инженерного изучения. Назначение ремонта, оценка запасов и экономической эффективности требуют дополнительных данных.
